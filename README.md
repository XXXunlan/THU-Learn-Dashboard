# THU Learn Dashboard · 网络学堂 × 雨课堂

一个 Manifest V3 浏览器扩展，把清华大学网络学堂与雨课堂的课业信息合并到同一块面板上。登录后自动抓取本学期每门课的公告、文件与作业：作业按截止时间排序，显示倒计时与紧急度配色（已逾期 / 24 小时内 / 3 天内 / 7 天内 / 更远），已完成的作业默认隐藏；有说明和附件的会在卡片上标出，说明限两行、悬停看全文；点卡片即跳转对应页面，雨课堂的作业则在雨课堂打开。雨课堂是另一个平台、另一套账号体系，其作业会在刷新时一并抓取，按课程名自动归入同名课程，与网络学堂的作业混在同一列表里统一排序，并以「雨课堂」标记区分。此外还有角标显示 3 天内待交作业数、定时刷新、页面右下角悬浮入口。扩展只在你自己的浏览器里运行，账号密码与数据都不出本机；取证、自检等排障入口默认隐藏，可在设置里打开。

## 功能

| 需求 | 实现 |
| --- | --- |
| 获取当前学期的课程清单 | 复用浏览器已有会话；未登录时引导你完成统一身份认证（可自动填充账号密码）。课程按学期从站点自己的接口拉取，主修 + 辅修/双学位都取 |
| 公告 / 文件 / 作业用更直观的形式列举 | 整页面板：左侧课程栏，右侧按 **作业 / 公告 / 文件 / 全部** 分标签；支持搜索、按紧急度筛选、跨课程总览 |
| 标注截止日期、不列已完成的作业 | 卡片右侧显示截止时间 + 「剩 N 天 N 小时」，左侧色条按 逾期 / 24 小时 / 3 天 / 7 天 / 更远 五档上色；已交的作业默认过滤（可在设置里打开） |
| 点击面板跳转到对应页面 | 公告→详情页、文件→课件列表页、作业→按站点自身规则落到 `viewZy` / `viewTj` / `viewCj`；课程头部三个按钮→该课程的公告 / 文件 / 作业列表页 |
| 顺带抓雨课堂的作业 | 刷新时一并抓取，**按课程名并入网络学堂的同名课程**，带「雨课堂」标记，点开在雨课堂里打开 |

此外：扩展图标角标显示 3 天内待交作业数、可选的定时自动刷新、网络学堂页面右下角的悬浮入口。

## 安装

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`），打开右上角的**开发者模式**
2. 点**加载已解压的扩展程序**，选择本目录
3. 点扩展图标即可使用

要求 Chrome / Edge **111 或更高**（用到了 `world: "MAIN"` 内容脚本与 offscreen 文档）。本项目**零依赖、无构建步骤**，clone 下来即可加载，扩展目录本身就是产物。

## 使用

1. 点扩展图标，填入学号与密码，点**保存并打开登录页**（密码只发给你学校的登录页用于自动填充）
2. 在弹出的登录页里完成验证码 / 二次认证
3. 回到面板，检测到会话后会自动开始抓取
4. 点任意卡片跳转到对应页面

如果你已经在浏览器里登录过网络学堂，直接点**刷新**即可，不需要再填账号密码。

**面板速览**：左侧是全部课程（带待交作业数）+ 搜索框；顶部是连接状态、刷新、设置；作业标签页可按 全部 / 已逾期 / 24 小时内 / 3 天内 / 7 天内 / 未标注截止 筛选。

### 接入雨课堂

在设置里点一次**「授权雨课堂」**（授予 `*.yuketang.cn`），之后每次刷新都会把雨课堂的作业一并抓来。

- 雨课堂是**独立账号体系**，需要你自己在浏览器里登录过；扩展不碰你的账号密码。
- 作业按**课程名**归入网络学堂的同名课程；对不上的课程会在设置里明确列出，不会静默丢弃也不会硬塞。
- 雨课堂的作业**本来就没有「作业说明」字段**，卡片中间那行改显示它所在的章节名。

### 调试功能默认藏起来

取证、自检、诊断导出这些排障入口**默认不显示**（它们会开标签页、甚至连着打开几十个页面）。需要时在设置最下面打开**「显示调试与取证功能」**，它们就会出现。实现上是给这些元素加一个 `debug-only` 类，新增调试入口只要带上这个类即可自动被收纳。

## 它是怎么工作的

网络学堂 2018 版前端是**客户端渲染**的：课程列表页返回的 HTML 里只有空容器和 mustache 模板，公告 / 文件 / 作业列表都是 DataTables 服务端分页。所以「抓 HTML 再解析」这条路在真实站点上拿不到任何数据。

于是分两层：

- **第一层（默认）**：直接调站点自己的 JSON 接口 —— 快、全、可翻页。
- **第二层（兜底）**：接口参数对不上时，让浏览器自己去打开那个列表页，等站点把表格画出来，再从渲染好的 DOM 里读。

两层都失败才在面板上报错，并把失败原因写进诊断包。

接口参数**不靠猜**：`sniffer.js` 以 `document_start` 注入页面环境，记录站点自己发出的请求（URL + 方法 + 请求体 + **响应体**），扩展学会之后照着重放，只把课程 id 换掉。这是整个项目最重要的一条设计 —— 靠猜接口在这个站点上必然失败，实测中曾经 10 门课全部退回页面兜底。

雨课堂那条路径同理，只是走得更远：它的**课程列表接口是运行时认出来的**，连 XTBZ 这个必须带的请求头也是从站点自己的请求里学来的。

选择**零依赖 + 免构建**：用浏览器原生支持的 ES modules 直接写，没有 `node_modules` 黑箱，任何人 clone 下来就能跑，代价是没有 SFC/JSX 语法糖。

## 隐私与安全

- **账号密码**：默认只保存在 `chrome.storage.session`，**关闭浏览器即失效**，不写磁盘。只有显式勾选「记住密码」才会以**明文**写入 `chrome.storage.local`（扩展沙箱内，不加密）—— 这是为了方便自动填充。任何时候都可以在设置里清除。
- **密码不会被发到任何第三方**：只通过 `chrome.scripting` 注入到你学校自己的登录页表单里。
- **权限最小**：
  - 必需：`storage`、`tabs`、`alarms`、`offscreen`、`scripting`；主机权限仅 `learn.tsinghua.edu.cn`
  - 可选：`*.tsinghua.edu.cn`（用自动填充时申请）、`*.yuketang.cn`（用雨课堂时申请）
- **没有自己的后端**，所有请求直接发往 `learn.tsinghua.edu.cn` / `yuketang.cn`。
- **诊断包只在你手动导出时生成**，里面可能含课程与页面内容，分享前请自行检查。取证与诊断入口默认隐藏。

## 已知限制

- 登录必须由你本人在统一身份认证页面完成（验证码 / 二次认证），扩展不代劳。
- DataTables 参数名无法从前端压缩代码里完全确认，因此同时发送 1.9 与 1.10 两代命名的**超集**；站点若严格拒绝多余参数，会自动退回渲染兜底路径。
- 讨论 / 答疑 / 问卷板块尚未纳入（数据结构已预留）。
- **雨课堂的「已完成」是推断口径**：`done >= total`（题数做完）判为已完成。只观测到一条正向样本、没有反例可校验，因此面板上显示成「已完成 2/2 / 未完成 0/6」这种带进度的措辞，而不是权威的「已交 / 未交」。
- **雨课堂课程归类靠课程名**，名字差太多（例如一边带教师名）就可能对不上；对不上的课程会明确列出。
- 雨课堂需要你单独登录过；扩展只读它自己会话能拿到的数据，不代登录。
- 雨课堂的课程列表接口是运行时认出来的，改版后若认不出，会如实说明并退回「抠教室 id + 逐个核实」的兜底路径。

## 排障

先做这一步：**在浏览器里手动打开一次网络学堂页面**，让扩展读到页面的 `_csrf` 令牌，然后回面板刷新。多数问题出在这里。

| 现象 | 多半是 |
| --- | --- |
| 面板说未登录，但我明明登录了 | 会话判定会综合接口响应、同源标签页证据、页面特征三方取证。先按上面那步做；仍不行就打开调试开关，点「登录诊断」看每一步的实际证据 |
| 某个板块一直是空的 | 接口不通会自动退回渲染兜底（慢但更稳）。仍然空的话打开调试开关，**导出诊断包**，里面含抓取统计、错误与页面样本 |
| 作业没有「说明」 | 说明只存在于详情页，需要抓取结束后再补全一次（默认开启）。站点上本来就没写的，卡片会明说「该作业未填写说明」，与「未取到」区分开 |
| 刷新慢、进度条不动 | 主要耗时在补全说明与附件。可以在设置里关掉，或把「单次补全上限」调小。已完成的作业不补全 |
| 课程名显示成「课程 2026-2027-…」 | 某个接口版本没给课程名，扩展会去渲染后的页面补齐；仍失败说明两种途径都没拿到，属于站点数据问题 |
| 雨课堂没有作业 | 依次确认：设置里点过「授权雨课堂」、雨课堂那边自己登录过、点「自检雨课堂」看卡在哪一步 |
| 课程重复 / 每门课内容一模一样 | 这是早期版本共享辅助标签页导致的串课问题，已通过串行化修复。若复现请带诊断包反馈 |

## 技术说明：接口与数据来源

**这里的每一个接口路径与字段名都来自实机抓包，没有一处是推测的。** 站点改版时优先看 `src/api/endpoints.js` 与 `src/parsers/yuketang.js` 顶部的注释。

### 网络学堂

| 用途 | 接口 |
| --- | --- |
| 当前学期 | `/b/kc/zhjw_v_code_xnxq/getCurrentAndNextSemester` |
| 按学期取课程 | `/b/wlxt/kc/v_wlkc_xs_xkb_kcb_extend/student/loadCourseBySemesterId/{xnxq}/zh` |
| 公告 | `/b/wlxt/kcgg/wlkc_ggb/student/kcggListXs` |
| 文件 | `/b/wlxt/kj/wlkc_kjxxb/student/kjxxbByWlkcidAndSizeForStudent`（另有分类表 `kjflb/student/pageList`） |
| 作业 | `/b/wlxt/kczy/zy/student/index/zyListWj`（未交）、`zyListYjwg`（已交未改）、`zyListYpg`（已批改） |

- 所有 `pageList` 类接口都是 DataTables 风格的服务端分页，参数名靠嗅探学到的模板重放。
- 公告的已读状态用站点权威字段 `sfyd`（"是"/"否"）与 `ydsj`，**不用发布日期猜**。
- 响应外壳不止一种（`resultList` / `object` / `aaData` 二维数组），客户端会深挖并记录命中路径。

### 雨课堂

| 用途 | 接口 |
| --- | --- |
| 课程列表 | `/v2/api/web/courses/list`（**主路径是运行时识别**，这条是抓包得到后作为兜底） |
| 单课信息 + 签名 | `/v2/api/web/classrooms/{cid}?role=5` → `course_sign` |
| 章节树（作业在这） | `/mooc-api/v1/lms/learn/course/chapter?cid={cid}&sign={sign}&classroom_id={cid}&show_unpublished=0` |
| 完成度 | `/mooc-api/v1/lms/learn/course/schedule?cid={cid}&sign={sign}&classroom_id={cid}&is_h5=true` |
| 作业页地址 | `/ai-workspace/lms-graph/{cid}/exercise/{leaf_id}?is_chapter=1&node_id={chapter_id}` |

几个实测确证、且**踩过坑**的事实：

- 章节树里 **`leaf_type === 6` 就是作业**（课件类是 8）；`score_deadline` / `start_time` 是 **epoch 毫秒**；作业页地址里的 `node_id` **就是 `chapter_id`**。
- **课程列表接口不返回 `course_sign`**，而章节树与完成度都必须带它 —— 「认出课程列表」只是第一步。
- **「教室 id」与 `course_id` 是两个不同的编号**（实测 3206672 是教室、1363292 是课程），取 sign 时两个都要试，以单课接口真正答出来的为准。
- 雨课堂用 **HTTP 200 + `success:false` / `errcode!=0`** 表示失败。这种响应是合法 JSON，只看「能不能解析」会把它当成成功，于是**接口报错被读成「这门课没有作业」** —— 所以每次取数都显式检查。
- `mooc-api` 要求一个自定义请求头（实机报错原文 `XTBZ IS REQUIRED`）。它的值只存在于站点自己的请求里，猜不得，所以嗅探器对**一份逐一列出的白名单**（`xtbz` / `x-client` / `x-platform` / `university-id` …）记录 header 的**值**，其余一律只记名字。学到后持久化，只学一次。
- 叶子提取是**递归**的：实测样本里章节是平的，但雨课堂支持「章 → 节 → 叶子」嵌套，只读扁平那层会把嵌套课程误判成「没有内容」。
- 所有雨课堂请求优先由 **Service Worker 直连**（cookie 能带上时最快）；不行才改用**页面自己的源**发出，因为其会话 cookie 若是 `SameSite=Lax`，后台请求会被当成跨站而丢掉 cookie。

### 取证与自检

都藏在设置里的调试开关后面：

- **全面取证**：逐个打开课程主页 / 公告 / 文件 / 作业页面，把站点自己发出的请求与响应、页面结构骨架打包成一个 JSON。排查时跑一次就不用反复来回试。
- **雨课堂接口取证**：打开雨课堂并记录它发出的所有请求，供改版后重新对齐接口。
- **自检雨课堂**：把权限 → 登录 → 首页 → 认接口 → 逐课取 → 课程名匹配这条长链路的**每一环实际观测值**直接列出来。任何一个环节断了，在界面上都只表现为「没有雨课堂作业」这一个结果，光看结果是没法修的。
- **导出诊断包**：抓取统计、错误、日志与页面样本。

## 开发与测试

```bash
node tests/run.mjs      # 927 条断言，自带轻量 DOM，不需要浏览器
node tools/validate.mjs # 444 项静态校验
```

测试用对抗性审查的方式写：它一开始专门去**证伪**解析层的假设，抓出并固定了一批真实缺陷（页面身份误判、把「1.2 MB」当成 1 月 2 日、把提交日期当截止时间、短课程列表里每门课继承第一张卡片的教师……）。缺陷修好后那组被改写成回归测试。

静态校验检查的是那些「一错就让扩展完全打不开」的东西：manifest 引用、import 解析（含命名导出）、HTML 资源引用、`$('#id')` 与 HTML 里 id 的对齐、消息协议两端是否一致。

```bash
  --enable-logging=stderr --virtual-time-budget=11000 --dump-dom \
  chrome-extension://ncgioopojlgncgpjkflkhijfojpnmipo/src/dashboard/dashboard.html
```

扩展 ID 由 `manifest.json` 里的 `key` 固定（那是**公钥**，可以公开；配套私钥绝不能提交）。stderr 里能看到 Service Worker 的启动日志。

### 面板渲染预览（不需要账号）

`tests/preview/mock-dashboard.html` 用**假数据**驱动真实面板，可在无头浏览器里检查卡片形态、倒计时、颜色档位与跳转链接：

```bash
msedge --headless=new --disable-gpu --no-sandbox --no-first-run \
  --user-data-dir=/tmp/prof --load-extension=<本目录> \
  --virtual-time-budget=9000 --dump-dom \
  chrome-extension://ncgioopojlgncgpjkflkhijfojpnmipo/tests/preview/mock-dashboard.html
```

页面顶部那行会打印自检结果（说明区高度与截断、悬停浮层、附件与雨课堂标记、已完成是否隐藏、调试开关是否生效）。

### 用真实页面验证解析器

`tests/minidom.mjs` 是零依赖的迷你 DOM，跑单测很方便，但它**扛不住真实页面**（会解析出空 body）。凡是要拿真实 HTML 验证解析器，都得用浏览器自己的 DOMParser：

```bash
# 把真实页面存成 tests/preview/real-detail.html，然后
msedge --headless=new --disable-gpu --allow-file-access-from-files --virtual-time-budget=6000 \
  --dump-dom "file:///<项目路径>/tests/preview/parse-real.html?fixture=real-detail.html"
```

> ⚠️ 存真实页面样本时记得先脱敏（姓名、学号、课程号、教室 id、`_csrf`），再放进仓库。

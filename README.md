## 2. 安装（加载已解压的扩展）

无需构建、无依赖、不需要 npm。

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录 `thu-learn-dashboard`
4. 首次安装会自动打开汇总面板；也可以点扩展图标 → 打开汇总面板

要求 Chrome / Edge **109 及以上**（用到了 `chrome.offscreen`）。

## 3. 使用

1. 点扩展图标，填入学号与密码，点 **保存并打开登录页**
   （扩展只把密码发给你学校的登录页，用来**自动填充**；见下面第 5 节的说明）

## 4. 它是怎么工作的（以及为什么这么设计）

### 4.1 真实站点的两个关键事实

这两点决定了整个架构，值得先讲清楚：

1. **网络学堂 2018 版前端是客户端渲染的。**
   课程列表页返回的 HTML 里**没有课程**，只有一个空的容器和一个 mustache 模板
   （`<script type="text/html" id="tablist">`，里面是 `{{value.kcid}}` 占位符）；
   公告 / 文件 / 作业三个列表页也都是 **DataTables 服务端分页**，原始 HTML 里没有数据行。
   → 所以「fetch 页面 HTML + DOMParser」这条常见路子在这里**拿不到任何内容**。

2. **登录已经换成学校统一身份认证（id.tsinghua.edu.cn），带验证码，旧接口已废弃。**
   → 所以不存在「扩展 POST 账号密码就登录成功」这回事。

### 4.2 因此的数据获取策略

```
                    ┌─ 第一层：直接调站点 JSON 接口（快、全、可翻页）
抓取一个板块 ────────┤   带 cookie + _csrf，DataTables 参数用“超集”
(公告/文件/作业)     │
                    └─ 第二层：兜底 —— 用不可见的后台标签页打开那个列表页，
                        等站点自己把表格画出来，把整页 HTML 交回离屏解析器
                        （再不行，退到内容脚本按表头定位列直接读表格）
```

- 第一层成功就完全不需要打开任何标签页，也不需要你先访问网络学堂。
- 第二层为什么可行：**站点自己的 JS 一定知道怎么取自己的数据**，我们只是借它的渲染结果。
- 两条兜底路径共用同一个解析引擎（`src/parsers/`），不会出现两套互相不一致的逻辑。

`_csrf` 令牌的处理：站点对 `/b/...` 的请求都会带 `_csrf=<uuid>` 查询参数。
它具体存在哪里无法从前端资源里 100% 确认（候选是 cookie `XSRF-TOKEN` / localStorage / 页面全局），
所以 `src/background/csrf.js` **按可靠性依次尝试多种来源**，并且最终以「接口能不能调通」为准：
拿不到就不带令牌请求一次，仍然失败就明确告诉你去浏览器里打开一次网络学堂（让扩展读到令牌），
而不是假装成功。


### 4.4 为什么是「零依赖 + 免构建」

原计划用 WXT/Vite + Vue，但这台开发机没有外网，`npm install` 不可能成功。
与其交付一个装不上的工程，不如**用浏览器原生支持的 ES modules 直接写**：
扩展目录本身就是产物，加载即用，评审者可以逐行读完每一个字节，没有 `node_modules` 黑箱。
代价是没有 SFC/JSX 这类语法糖，收益是**任何人 clone 下来就能跑**。

## 5. 隐私与安全（请务必看一眼）

- **账号密码**：默认只保存在 `chrome.storage.session`，**关闭浏览器即失效**，不写磁盘。
  只有你显式勾选「记住密码」时才会以**明文**写入 `chrome.storage.local`（扩展沙箱内，不加密）——
  这是为了方便自动填充，不勾选就没事。任何时候都可以在设置里「清除已保存的账号密码」。
- **密码不会被发到任何第三方**：它只通过 `chrome.scripting` 注入到你学校自己的登录页表单里。
- **权限是最小的**：
  - 必需：`storage`、`tabs`、`alarms`、`offscreen`、`scripting`，主机权限仅 `learn.tsinghua.edu.cn`
  - 可选：`*.tsinghua.edu.cn`（只有你要用「自动填充统一身份认证页面」时才会申请）
- **不到外部服务器发数据**：扩展没有自己的后端，所有请求都直接发往 `learn.tsinghua.edu.cn`。

## 6. 排障

### 6.1 「我明明登录了，面板却说未登录」

这是被真实反馈出来的问题，根因有四个，都已修掉并写了回归测试：

| # | 缺陷 | 为什么会误判 |
| --- | --- | --- |
| A | 把「课程列表页发生重定向」当成未登录 | 站点对**已登录**的请求也会重定向：它会把 session id 重写进 URL（`/f/wlxt/index/course/student/;jsessionid=…wlxt20181?websiteShowLanguage=zh_CN`）。于是登录成功反而被判成未登录 |
| B | 用 `/j_spring_security/` 当登录页标记 | 这个前缀同时匹配 `/f/j_spring_security_logout` —— 那恰恰是**登录之后**页面上才出现的退出链接。现在只认登录提交端点 `j_spring_security_check` |
| C | 界面只显示上次缓存的会话状态 | 面板/弹窗打开时从不重新校验，`loggedIn: false` 一旦写进去就一直是 false。现在每次打开都会重新确认 |
| D | 后台 fetch 可能带不上 cookie（SameSite 等） | 加了「同源地面证据」：内容脚本就跑在站点页面上，它看到课程容器就采信它；同时抓取整体降级到页面兜底路径，而不是直接报错退出 |

现在判定会话的顺序是：**JSON 接口 > 打开标签页里的同源证据 > 页面特征**，并且每一步的原始证据都会保留。

### 6.2 登录诊断（出问题先跑这个）

点面板上的登录按钮 → **登录诊断**。它会把判定用到的每一步摊开给你看：

```
结论：未登录（依据：api-redirect）
说明：接口被重定向（HTTP 3xx），说明会话已失效 —— 需要登录

✓ 扩展权限
    learn.tsinghua.edu.cn：清单内必需权限；id.tsinghua.edu.cn：未授权（只影响登录页自动填充）
✓ 页面自述（来自内容脚本）
    地址 https://learn.tsinghua.edu.cn/...；标题「网络学堂」；密码框=false；
    课程容器=true；页面上渲染出的课程数=8；可见 cookie=JSESSIONID,...；能找到 _csrf=true
✓ _csrf 令牌
    已取得（来源：tab:page-helper）
✗ 接口探测（会话的权威证据）
    结果类型=redirect，HTTP 0
✓ 课程列表页
    HTTP 200；最终地址 ...；密码框=False；像登录页=False；有课程容器=True
```

**怎么读它：**

- 「页面自述」里有课程数、却「接口探测」被重定向 → 是 **D**：后台请求没带上 cookie，抓取会自动走页面兜底
- 「页面自述」显示密码框=true → 浏览器里确实没登录，去登录即可
- 「_csrf 令牌」= 没有 → 在浏览器里打开一次网络学堂页面再重试
- 「课程列表页」请求失败 → 网络/权限问题，不是登录问题

### 6.3 「课程被重复列举」/ 每门课内容都一样

真实上报的问题，诊断包把它钉死了：`stats.usedFallback = 10`（10 门课全部退回页面兜底），
命中的策略是 `tab:selector:li` 与 `tab:repeated:li.kc1@…#ul.droppanel`。

**根因**：兜底解析退到了裸 `li` 选择器，而网络学堂的**左侧导航就是一堆 `li`**，
并且**每门课的导航里都列着所有课程**。于是每门课都抓到同一份导航内容 ——
面板上看起来就是「课程被重复列举了好多次」，而且一条截止时间都解析不出来
（因为那不是作业表，根本没有「截止日期」这一列）。

**修法**（三道，缺一不可）：

1. 候选选择器改成**站点自己的真实容器优先**（`#ggalltable` / `#kjalltable` / `#zyalltable` /
   `#examplesearch` / `table.dataTable`），并移除裸 `li` 与 `.row` —— 它们在真实页面上
   首先命中的永远是导航。
2. 把站点的导航容器（`.navlef` 左菜单、`.droppanel` 导航下拉、`.morebtn`）加入噪声名单。
   注意 `.rtcon` 是**右侧内容区外壳**，绝不能当噪声 —— 会把真实列表一起过滤掉
   （这个错误是写测试时才发现并修掉的）。
3. 加一道**链接特征闸门**（`KIND_URL_PATTERN`）：一份真正的作业列表里，条目链接必然长成
   `/f/wlxt/kczy/zy/student/viewXxx`。凡是链接特征完全对不上的候选，无论条目多少一律丢弃。
   这道闸门是根治点 —— 它不依赖选择器猜得准不准，只依赖「这份数据像不像这个板块」。

### 6.4 课程名显示成「课程 2026-2027-1000000001」

诊断包里 10/10 门课的 `name` 都退化成占位符、`counts` 全为 0，说明**接口返回的课程行里
字段名与我们预期的不一致**。现在改成：只要发现课程名是占位符，就自动去**渲染后的课程列表页**
把真实课程名与教师补齐（按 `wlkcid` 合并）。

### 6.5 接口那一路为什么一直失败 —— 让扩展自己学

`usedFallback: 10` 说明靠猜 DataTables 参数行不通。v1.1.0 起加了**请求嗅探**：

- `src/content/sniffer.js` 以 `world: "MAIN"`、`document_start` 注入，包住页面自己的
  `XMLHttpRequest` / `fetch`，只记录不修改、不阻塞；
- 兜底路径打开课程页时，顺带把站点自己发的 `/b/…pageList` 请求记下来，
  由 `src/api/learned.js` 变成模板：换掉 `wlkcid`、换掉 `_csrf`、去掉易变参数；
- 下次抓取**优先重放模板** —— 参数是站点的原话，不需要我们猜。

所以第一次抓取可能偏慢（要走页面兜底），之后会明显变快。模板会写进诊断包的
`learnedTemplates` 字段，接口到底通没通一看便知。

（这条需要 Chrome/Edge 111+，`manifest.json` 里的 `minimum_chrome_version` 已相应提高。）

### 6.6 好几门课的内容一模一样 / 某条作业重复出现

这是**兜底用的隐藏标签页被并发抢占**造成的，很隐蔽：

课程是并发抓取的（默认 4），而兜底路径只有**一个**隐藏标签页。A 课把它导航到自己的页面后，
B 课立刻又把它导航走；A 课等到的"渲染完成"其实是 B 课的页面 —— **A 课拿到的是 B 课的数据**。
诊断包的证据很直白：4 门不同的课都返回了同一条 `教学日历`，而 URL 里的 `wlkcid` 指向的是另一门课。

修法：用一条 Promise 队列把标签页访问**串行化**，一次只服务一个请求；另外在取快照时校验
页面地址确实是请求的那个，不符就打警告。

### 6.7 作业里出现「没有您要搜索的内容」「表中数据为空」

那是 **DataTables 在无数据时塞进 `tbody` 的占位行**（`<td class="dataTables_empty">`），
它长得和真数据一模一样（有 td、有文本），于是被当成条目收进了面板。
现在在解析层与内容脚本两处都按 `EMPTY_STATE_RE` 过滤掉。

### 6.8 接口的真实格式（靠嗅探学到的）

`sentinel`：诊断包里的 `learnedTemplates` 给出了站点自己的请求长什么样，和我原先猜的完全不同：

```
POST /b/wlxt/kcgg/wlkc_ggb/student/pageListXsbyWgq?_csrf=<uuid>
body: aoData=[{"name":"sEcho","value":1},{"name":"iColumns","value":5},
              {"name":"mDataProp_0","value":"bt"},...,
              {"name":"wlkcid","value":"2026-2027-1000000003"}]
```

要点：**POST**、参数在 body 里叫 **`aoData`**（DataTables 1.9 的 `{name,value}` 数组格式）、
端点叫 `pageListXsbyWgq` 而不是 `pageListXsSearch`。

之前 `retargetRequest` 只认 `defaultSearchCondition`，**body 里的课程 id 从来没被替换过**，
模板会一直请求同一门课。现在 `aoData` 与路径中的课程 id 都会被正确替换。

### 6.9 抓取太慢、进度条不动、标签页乱跳

真实反馈，日志把三个原因都说清楚了（那次抓取总耗时 **181 秒**）：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 慢 | 每个兜底页面**固定等 3.5 秒**，30 个页面就是 105 秒纯等待 | 改成**轮询**"目标表格渲染好了吗"：一有行就立刻走（通常 0.5～1.5 秒），只有真的空列表才等到上限 |
| 进度条不动 | 进度按**整门课**推进，而 4 个并发 worker 全堵在同一个辅助标签页上排队 | 进度改为按**板块**推进（3 个/门课） |
| 标签页乱跳 | `tabs.create({active:false})` 只是不抢焦点，**标签页仍然留在用户标签栏里**并随抓取不停变 URL | 辅助页面移入一个**独立的、最小化的窗口**，用户基本看不到 |

另外还砍掉了绝大部分兜底次数：**先单独抓第一门课**，它的兜底会把站点自己的接口请求
学成模板；后面的课直接走接口，不再一个个开页面渲染。实测兜底页面加载可从 30 次降到 3 次左右。

顺带去掉了一处浪费：以前每次页面加载完成都会强刷一次 `_csrf`，现在只在没有令牌时才取。

### 6.10 某个板块抓不到内容（例如文件全空）

诊断包现在会带上**失败页面的精简 HTML**（去掉 script/style/注释再截断，300KB 的页面通常压到 20KB 以内）。
这是定位这类问题最快的办法：直接看那一页到底有哪些元素。

> 这里踩过一个坑：第一版只把快照的**元信息**放进了导出包，带 HTML 的那份留在了外层，
> 面板导出时丢掉了 —— 等于白存。现在 HTML 会随诊断包一起导出。

另外加了一条针对性兜底：**课程主页**。站点把公告 / 文件 / 作业三张表
（`#ggalltable` / `#kjalltable` / `#zyalltable`）都聚合在课程主页上，
所以某个板块的"专用列表页"拿不到东西时，改从课程主页取 ——
每门课只拉一次，三个板块共用同一份结果。

### 6.11 响应外壳：站点返回的不止一种形状

真实观测到至少三种：

```
{message:'success', resultList:[...]}
{result:true, msg:'success', object:{...}}        ← 站点实际用的
{sEcho, iTotalRecords, aaData:[[...], [...]]}     ← DataTables 1.9，行是数组
```

最后一种要靠请求体里学到的列定义（`mDataProp_0='bt'`…）才能还原成对象。
所以 `extractRowsDetailed` 现在既认常见字段名（含 `object` / `obj` / `payload`），
**也会在兜底时深挖任何不认识的键**——站点换个包装不至于整个失效。
命中的路径会记进 `matchedKey`，诊断时一眼能看出是靠哪条路挖到的。

### 6.12 文件一栏始终为空（已定位并修复）

**根因**：我一直在调用错误的接口。全量取证抓到站点的真实请求后，答案很清楚 ——
文件的数据一直都在，只是那个端点我从来没找对过：

```
GET /b/wlxt/kj/wlkc_kjxxb/student/kjxxbByWlkcidAndSizeForStudent?wlkcid=X&size=300
→ {"result":"success","msg":null,"object":[
     {"bt":"1-数据科学介绍2026","wjlx":"pdf","wjdx":10831880,"fileSize":"10.0M",
      "scsj":"2026-09-15 14:06","wjid":"2023310802_KJ_…","kjxxid":"…","kjflid":"INITWJ152230837"}]}
```

`object` 直接就是对象数组，字段名与 `normalizeFile` 完全对得上。
备用路径是「课件分类 → 逐个分类取文件」，其中分类内文件的响应是**二维数组**，
只能按位置取字段 —— 那份位置化字段表（`FILE_CATEGORY_COLUMNS`）也是照真实样本逐位对齐的，
没有把握的位置一律留成 `_5` 这样的占位名，**绝不硬安字段名**（猜错字段比留空更糟）。

同一批取证还纠正了另外三处：

| 我原先以为 | 实际是 |
| --- | --- |
| 公告 `…/pageListXsSearch` | `…/kcggListXs?wlkcid=X&size=N`（简单 GET，`object.aaData`） |
| 作业 `/b/kc/v_xszy_search/student/pageList` | 站点按状态分了三个：`zyListWj`（未交）/ `zyListYjwg`（已交未改）/ `zyListYpg`（已批改），三个都取再合并 |
| 课程主页 `/f/wlxt/course/index?wlkcid=` | `/f/wlxt/index/course/student/course?wlkcid=` |

### 6.13 「学期接口没返回可用值」这类提示

两个层面的问题，都修了。

**第一层：那个接口本来就给不出东西。** 实测 `getCurrentAndNextSemester` 的 `resultList` 是空的，
所以不能再只靠它。现在的策略是三级，而且**最终以课程数据为准**：

1. **用户在设置里手动指定**（`设置 → 学期`，形如 `2026-2027-1`）—— 永远说了算；
2. **学期接口**：不再按字段名解析，而是直接在序列化结果里找形如 `2026-2027-1` 的串 ——
   它包几层、字段叫什么都能捞出来；
3. **按日期推断 + 用课程清单反证**：拿推断的学期去查课程，有课就说明猜对了；
   没课就自动试前后相邻的学期。猜错也能自己纠正回来。

**第二层：这条提示压根不该是警告。** 以前我把这类**信息性说明**也塞进了 `errors`，
于是面板无脑弹「部分内容可能不完整」—— 其实什么都没坏。现在 `notes`（信息）与
`errors`（真问题）分开存：前者进诊断包，后者才触发提示条。
只有三级全失败（真的确定不了学期）才会提示你手动填，并且带一个「去设置」按钮。

### 6.14 公告的「未读」标记一直不消失

**根因**：我用「发布日期在 3 天内」当未读判断 —— 那跟读没读根本没关系，
所以已读的公告也一直挂着 NEW，读完刷新当然还在。

站点其实给了权威字段（取证得到的真实响应）：

```json
{"ggid":"…","bt":"课程微信群","fbrxm":"刘文瑄","fbsj":"2026-09-15 08:52",
 "ydsj":"2026-09-15",   ← 阅读时间
 "sfyd":"是",           ← 是否已读（是/否），这才是判断依据
 "ggnrStr":"请大家及时加入…",  ← 可读正文（ggnr 是 base64，不能直接用）
 "fjmc":"mmqrcode…png", "sfqd":"1"}
```

现在优先用 `sfyd`，其次用 `ydsj`（空=未读），两者都没有才保守判为未读。
DOM 兜底路径判断不了时置 `null`（未知）—— **不谎报成已读**。
顺带把正文（`ggnrStr`）、附件名（`fjmc`）、置顶（`sfqd`）也显示出来了。

### 6.15 「N 门课程有部分板块抓取失败」

**根因**：我把「接口正常应答、但没有内容」也记成了错误。
一门课没有作业、没有课件是**常态**，不该报警。现在只有真的没走通
（`method === 'failed'` / 没找到任何候选）才算失败 —— 这条规则抽成了
可单测的 `isSectionFailure()`。

这和 6.13 是同一类毛病：**把信息当成错误**，导致面板弹出没有信息量的警告。

### 6.16 其他

| --- | --- |
| 课程数为 0 | 学期码判断问题，或本学期确实没有选课。诊断包里会记录实际使用的学期码 |

## 7. 作业说明与附件是怎么来的

作业列表接口（`zyListWj` / `zyListYjwg` / `zyListYpg`）返回的是**表格行**，
按站点自己的列定义只有标题、状态、截止时间、成绩 —— **没有作业说明，也没有附件清单**。
那两样在**作业详情页**（`viewZy` / `viewTj` / `viewCj`）上。

所以做成了两级：

1. **先看列表行**：不同接口版本偶尔会带（`nr`/`yq`/`ms`/`fjmc` 等字段名都试一遍），
   有就直接用，不花额外流量；
2. **没有就补全详情页**：主抓取完成、缓存已落盘**之后**再单独跑一步，
   抓详情页 HTML 并解析。详情页是服务端渲染的 JSP，直接 fetch 即可，不用开标签页。

补全这一步的三个取舍：

- **不拖慢主流程**：主抓取先落盘，所以你看到的一秒刷新不受影响；补全完成后再写一次缓存。
- **限量 + 并发**：默认最多 20 条待交作业、并发 4；已完成的作业根本不抓。
- **失败不影响已有数据**：补全挂了只是没有说明/附件，其余照常。

解析「作业说明」的原则是**按页面上的标签文字找**（`作业说明` / `作业内容` / `作业要求`…），
而不是赌 class 名；实在没有标签才退到「正文里最长的一段文本」，并标出来源是兜底。
附件则按「链接里带 `downloadFile`/`wjid`」或「链接文字像文件名」来认。
**找不到就什么都不显示，绝不编造内容。**

### 抓取收尾不该「卡一会」

补全说明这一步原本会在结尾明显停顿，两个来源都修掉了：

| 原因 | 修法 |
| --- | --- |
| 详情页**没有列表表格**，而等待逻辑是「等表格出现」——只能把超时耗满，每条作业白等 3 秒 | 新增 `waitFor: 'settle'`：**等正文长度稳定**就立刻走（通常 1 秒左右）。列表页仍用原来的「等表格」，两种页面各用各的 |
| 作业说明很少变，却**每次刷新都重新渲染一遍**；20 条待交作业就是 30 秒 | 补全结果按作业 id **缓存 12 小时**，命中就直接用，一条都不必再开页面 |

进度也不再是干等：收尾阶段会报 `补全作业说明与附件 2/4…`，面板上看得出它在动。

### 说明取不到时，改用渲染后的页面

作业详情页的「作业说明」是**页面 JS 填进去的** —— 服务端返回的原始 HTML 里那个容器是空的。
这一条把之前两个相反的故障串起来了：

| 做法 | 结果 |
| --- | --- |
| 旧代码：精确匹配拿到空 → 退到「宽松匹配」 | 抓到字段之上的大容器，把 **`作业内容及要求：` 之后的整页内容**当成说明 |
| 上一版：精确匹配拿到空 → **如实返回空** | **一条说明都没有** |

两条都不对。正确做法是**原始 HTML 空 → 换成浏览器渲染后的页面再解析**：

1. 先直接 `fetch` 原始 HTML 解析（快，不用开页面）；
2. 若**说明为空** → 用辅助标签页把页面渲染出来，再解析一次（附件取并集，别丢掉原始 HTML 里已有的）。

> ⚠️ 判据只能是**说明本身**。第一版把它写成「说明**和**附件都为空才重试」，
> 而附件链接本来就是服务端渲染的、原始 HTML 里就有 —— 于是「说明空 + 附件有」
> 这个最常见的组合被误判成成功，**重试永远不触发**。
> 实测仪表：`raw: {len: 0, source: 'empty:作业说明'}` 而 `renderedRetry: 0`。
> 这条现在有专门的测试钉住。

补全的每一步都会记进 `stats.enrich.samples`（`raw`/`rendered` 各自的来源与长度、最终用了哪条路），
所以下次出问题时，**一份普通诊断包就能看出卡在哪一步**，不必再单独取证。
万一连渲染后都拿不到说明，那条作业的**原始 HTML 会被自动存进快照**，
诊断包里直接就能看到那一页长什么样。

### 说明只取「作业说明」这个字段

详情页是一串字段排下来的：

```html
<div class="ttee">作业内容及要求：</div>          <!-- ← 区块标题，不是字段 -->
<div class="list"><div class="left">作业标题</div><div class="right">…</div></div>
<div class="list"><div class="left">作业说明</div><div class="right">…要的就是这里…</div></div>
<div class="list fujian"><div class="left">作业附件</div><div class="right">…</div></div>
<div class="list"><div class="left">发布对象</div><div class="right">…</div></div>
```

有三处坑，都是被真实数据打出来的：

1. **区块标题被当成字段标签。** 旧的「宽松匹配」只看 `startsWith`，
   于是 `作业内容及要求：` 被当成标签 `作业内容`，切掉后剩 `及要求：`；
   而字段之上的大容器（`.boxbox` / `.detail`）文字正好以这个标题开头 ——
   结果**整页内容**都成了作业说明。
   → 现在宽松匹配要求标签后面**紧跟冒号或空白**，`作业要求及内容：` 这种直接排除。

2. **精确匹配选到了包着标签的父容器。** 内容为空时，父容器的文字也恰好等于标签，
   而它在文档顺序里更靠前，于是从父容器的位置开始取，把后面的字段全吞进来。
   → 现在同名元素里**取最「小」的那个**（子元素最少）。

3. **容器判定误杀正常说明。** 一开始我按全文去数「作业附件」「截止时间」这些词，
   可正文里本来就会提到它们（「请从本窗口作业附件中下载模板」「截止时间：9月22日」）。
   → 现在**只看开头 60 字**，且要求那里确实是一个字段标签或区块标题。

另外：字段存在但**内容为空**时，说明就是空 —— 不会退到别的字段去抓。
`descriptionSource` 会标明来源（`label:作业说明` / `empty:作业说明` / `longest-block`），
排查时一眼能看出它是怎么来的。

**附件要合并**：真实页面上一个附件有**两个链接** —— 文件名（`openNewWindow?fileId=…`）
和旁边的「下载」按钮（`downloadFile/…`）。不按文件 id 合并就会显示成两个附件。
合并后保留「像文件名」的那个名字，并优先使用 `openNewWindow` 里内嵌的
`downloadUrl`（那才是能直接下载的地址）。

**换行要保留**：说明里大量使用 `<p>` / `<ol><li>`，像 `textContent` 那样全拼成一行的话，
两行截断出来是一团读不通的字。现在块级元素之间保留换行。

界面上：说明放在标题与截止时间之间的中段，最多两行、超出省略，**鼠标移上去弹出全文**
（原生 `title` 有延迟、长度也受限，所以自己做了一个浮层，会自动避开视口边缘）；
悬停**整张卡片**都能触发，不必精确对准那两行窄条。
有附件的作业在**标题右侧**显示「📎 N附件」，悬停可以看到附件名清单。

### 验证解析器的正确姿势：别用迷你 DOM

`tests/minidom.mjs` 是零依赖的迷你 DOM，用来跑单元测试很方便，但它**扛不住真实页面**
（实测直接解析出空 body）。所以凡是「拿真实 HTML 验证解析器」的场合，都要用浏览器自己的 DOMParser：

```bash
# 把真实页面存成 tests/preview/real-detail.html，然后
msedge --headless=new --disable-gpu --allow-file-access-from-files --virtual-time-budget=6000 \
  --dump-dom "file:///<项目路径>/tests/preview/parse-real.html?fixture=real-detail.html"
```

结果（说明来源、正文、附件列表）会以 JSON 写进页面里。
这个页面在排查「说明/附件取不到」时非常有用 —— 一次就能看到解析器在真实 HTML 上的实际输出。

> 顺带修掉一个真 bug：诊断包的 `slimHtml` 原先把脚本替换成 `<script/>`，
> 而 HTML 里 `<script/>` **不是自闭合标签**，真实浏览器会把后面整个文档吞进脚本内容，
> 于是导出的快照再用 DOMParser 解析时 body 是空的。现在换成注释标记。

如果某天站点改版导致说明取不到，跑一次「全面取证」就能看到作业详情页的真实 HTML
（取证流程里已经加了这一页），照着调解析器即可。

## 8. 雨课堂（另一个平台，作业已接入）

雨课堂（`pro.yuketang.cn`）有**独立的账号体系**，而且是纯前端 SPA。它的作业现在会
**在每次刷新时一起抓下来，按课程名并到网络学堂的同名课程里**，卡片上带「雨课堂」标记。

用法：设置里点一次 **「授权雨课堂」**（授予 `*.yuketang.cn`），然后照常刷新即可。
雨课堂那边需要你自己在浏览器里登录过 —— 扩展不碰你的账号密码。

**如果看不到雨课堂作业，先点一次「自检雨课堂」。** 这条链路很长
（权限 → 登录 → 首页 → 认接口 → 逐课取 → 课程名匹配），任何一环断了在界面上都只表现为
「没有雨课堂作业」这一个结果，光看结果是没法修的。自检会把每一环的**实际观测值**直接列出来：

1. 有没有 `*.yuketang.cn` 的权限；
2. **雨课堂到底登录了没有** —— 同一个接口发两次，一次由扩展后台发、一次由页面自己发，
   两条路的结果都摆出来（这也能顺便说明 cookie 有没有被 SameSite 挡住）；
3. 首页加载出来的地址、标题、正文长度与开头；
4. 采集到多少条请求、都是哪些接口；
5. 课程列表认出没有；**没认出来的话，把所有被考虑过但被拒的对象数组连同拒绝原因列出来**
   （是"请求没采到"还是"响应形状变了"，一眼就能分清）；
6. 兜底能抠到几个教室 id；
7. 识别到的雨课堂课程分别对上了网络学堂的哪一门（对不上会明确标出）。

### 8.1 用到的接口（**全部来自实机抓包**，没有一处是猜的）

| 用途 | 接口 |
| --- | --- |
| 课程列表 | `GET /v2/api/web/courses/list`（**主路径是运行时识别**，这条是实机抓包得到后作为兜底） |
| 单课信息 + 签名 | `GET /v2/api/web/classrooms/{cid}?role=5` → `course_sign` |
| 章节树（作业在这） | `GET /mooc-api/v1/lms/learn/course/chapter?cid={cid}&sign={sign}&classroom_id={cid}&show_unpublished=0` |
| 完成度 | `GET /mooc-api/v1/lms/learn/course/schedule?cid={cid}&sign={sign}&classroom_id={cid}&is_h5=true` |
| 作业详情 | `GET /mooc-api/v1/lms/learn/leaf_info/{cid}/{leaf_id}/?classroom_id={cid}` |
| 作业页地址 | `/ai-workspace/lms-graph/{cid}/exercise/{leaf_id}?is_chapter=1&node_id={chapter_id}` |

几个**实测确证**的事实：

- 章节树里 **`leaf_type === 6` 就是作业**（实测名字为「第0次作业」「第一周作业」「第一次作业」），
  课件类叶子是 `leaf_type === 8`；
- `score_deadline` / `start_time` 是 **epoch 毫秒**；
- 作业页地址里的 `node_id` **就是 `chapter_id`** —— 用两条独立抓包互校过；
- 完成度 `leaf_schedules[leaf_id]` 有两种形状：`{total, done}`（作业这类多题叶子）、
  `标量 1`（视频/课件这类整片叶子）；
- ⚠️ **课程列表接口不返回 `course_sign`**，它只出现在单课接口上。而章节树与完成度**都必须带 sign**，
  所以「认出课程列表」只是第一步，每门课还得单独再问一次单课接口 —— 这一步漏了的话，
  表现就是"一门课的作业都取不到"。
- ⚠️ **「教室 id」与 `course_id` 是两个不同的编号**（实测 3000001 是教室、4000001 是课程），
  而列表接口给的是哪一个并不固定 —— 所以取 sign 时两个都试，**以单课接口真正答出来的那个为准**。
- ⚠️ **雨课堂用 HTTP 200 + `success:false` / `errcode!=0` 表示失败**
  （实机见过 `{"msg":"数据错误","error_code":20002,"data":{},"success":false}`）。
  这种响应是**合法 JSON**，只看"能不能解析"就会把它当成成功，
  于是「接口报错」被读成「这门课没有作业」—— 一个会安静骗过所有人的 bug。所以每次取数都显式查 `apiError()`。
- ⚠️ **叶子提取是递归的**。实测样本里章节是平的（每个章节直接挂 `section_leaf_list`），
  但雨课堂本身支持「章 → 节 → 叶子」嵌套；只读扁平那一层的话，嵌套课程会得到"一个叶子都没有"，
  而那跟"这门课确实没内容"长得一模一样，极难分辨。
- ⚠️ **`mooc-api` 要求一个自定义请求头**（实机报错原文：`{"msg":"XTBZ IS REQUIRED","error_code":40000,"success":false}`）。
  这个头的值**只存在于站点自己发出的请求里**，猜值是绝对不行的。
  所以嗅探器会把它学下来：`sniffer.js` 除了记 header 名字，还对**一份逐一列出的白名单**
  （`xtbz` / `x-client` / `x-platform` / `x-requested-with` / `university-id` …）**记值**。
  方向是"默认不记、特例才记"，`Authorization` / `Cookie` 这类永远不会被记下来。
  学到之后持久化在 `storage.local` 的 `yktHeaders` 里（和网络学堂的「接口模板」一个思路）。
  万一以后缺的是别的头，报错信息里会写出它的名字，照着加进白名单即可。

### 8.2 课程列表：不猜接口，而是"认"出来

上一轮取证**没有抓到课程列表那一次请求**（录制时没停在首页），所以它的路径我并不知道。
与其猜一个 `/v2/api/web/classrooms?role=5` 蒙上去，不如让扩展自己去看：

1. 在不可见的辅助标签页里打开雨课堂首页 —— 首页一定会去取课程列表；
2. `pickClassroomList()` 从**站点自己发出的真实响应**里认出哪一个是课程列表：
   先看响应里有没有 ≥2 个课程专有字段（`course_sign` / `course_name` / `uv_id` …），
   再看路径与结构；
3. 认不出来就退一步：从**请求过的 URL** 和页面 HTML 里抠出教室 id，
   再逐个用**已确证的**单课信息接口回填权威名称 —— 抠错了也不会污染数据，最多白跑几次。

> `pickClassroomList` 有一条**硬闸门**：带 `leaf_type` / `chapter_id` / `section_leaf_list`
> 这类标记的对象，以及挂在 `course_chapter` 这类键下面的数组，一律不是课程列表。
> 这条是被测试逼出来的 —— 章节树的对象也有 `id` 和 `name`，只看这两样就会把章节当成课程，
> 然后拿章节 id 去当教室 id 查。

### 8.3 请求由**页面自己**发出（一个容易踩的坑）

所有雨课堂接口都由辅助标签页里的 `collector.js` 用 `credentials: 'same-origin'` 发出，
**不是**由 Service Worker 发。原因：雨课堂的会话 cookie 大概率是 `SameSite=Lax`，
而扩展后台发出的请求会被浏览器视为跨站，那种情况下 cookie 根本不会带上，接口直接返回未登录。

同理，采集脚本注册在 `document_start` —— 首页那次列表请求可能在 `document_idle` 之前
就已经发完了，晚一步注入就永远听不到它。

### 8.4 归类与状态（含一处**明确的推断**）

- **归类靠课程名**：归一化（全角→半角、去空白、去 `2026秋-` 前缀、去 `-5` 班号后缀、去括号）后
  先精确相等、再互相包含（两边长度都 ≥ 4 才允许，免得「英语」匹配到「大学英语」）。
  对不上的课程**如实报告**，绝不硬塞；如果那门课还有作业没地方放，会在面板上报警。
- **状态**：`done >= total` 判为已完成，否则未完成。⚠️ **这一条是推断，不是确证** ——
  我只观测到「第0次作业 total=2 done=2」这一条正向样本，没有反例可校验。
  所以面板上把它显示成「已完成 2/2 / 未完成 0/6」这种**带题数进度**的措辞，
  而不是伪装成网络学堂那种权威的「已交 / 未交」，方便你一眼核对。
- **没有说明字段**：雨课堂作业本来就没有「作业说明」这种东西，所以不会去抓详情页补全
  （`enrich.js` 会跳过 `platform === 'yuketang'` 的条目），卡片中间那行改显示**所在章节名**。

### 8.5 接口取证工具（改版时才需要）

设置里的「开始记录雨课堂 → 结束记录并导出」仍然保留。站点改版、或者上面哪一步认不出来时，
跑一次这个就能拿到一份完整接口清单：

**「开始记录雨课堂」**：申请 `*.yuketang.cn` 权限，动态注册两个内容脚本
（`sniffer.js` 在页面环境里捕获请求，`collector.js` 把记录实时回传后台），然后打开雨课堂首页。
你按 **首页课程列表 → 进一门课 → 作业列表 → 打开一份作业** 的顺序点一遍，
再回来点「结束记录并导出」，得到的 JSON 里包含：

- **站点自己发出的每个接口**：URL、方法、请求体、**响应体**、header 名（不记值）
- 按「方法 + 路径」归类并计数（同一接口被轮询多次只算一类）
- 页面结构：列表容器、表格、localStorage/sessionStorage 的**键名**、可见链接、
  以及**渲染后的正文**（SPA 的字段名常常只在界面上露出来，而原始 HTML 前 20 万字符全是脚本）

**为什么每捕获一条就立刻回传后台**：SPA 会不停换页，页面一导航，页面里的缓冲就没了；
只有送进后台，跨页面的记录才连得起来。

嗅探器是通用化的：不写死路径，而是「同源 + 非静态资源」；对 `*.yuketang.cn` 还特意放宽成
**同一主域**（雨课堂是跨子域架构，教室信息里的 `university_domain` 就指向别的子域）——
上一轮取证漏掉课程列表接口，很可能就是这个原因。

## 9. 全面取证（一次性收集，排查问题首选）

> 这个功能**默认是隐藏的**：先在设置最下面打开「显示调试与取证功能」。
> 同样被收纳的还有「自检雨课堂」「雨课堂接口取证」「导出诊断包」和侧边栏的「导出诊断」。

排查这个站点最费时间的不是修，而是**来回试**：列表页是「聚合页 + 标签切换 + 服务端分页」，
接口参数只能从站点自己的请求里学，页面结构又必须看渲染后的结果。

所以面板设置里有一个 **「开始全面取证并下载」**：点一次，它会

1. 逐个打开**课程主页 / 公告 / 文件 / 作业**四类页面，每个页面还会**点开对应标签**再取一次
   （站点只有点了标签才去加载那个板块的数据）；
2. 记录每一页上**站点自己发出的 `/b/` 请求：URL + 方法 + 请求体 + 响应体**
   （响应体是最值钱的部分 —— 它直接说明字段叫什么、以及"是不是根本没返回数据"）；
3. 提取页面的**结构骨架**：每张表的 id/class、表头文字、行数、首行 HTML、
   空表占位、`tabchange` 标签链接；
4. 顺带保存**精简后的整页 HTML**（去掉 script/style/注释，但保留全部元素）；
5. 直接调用一批**候选接口**（GET 与 POST+aoData 两种形式），把原始响应也带上。

产出是一个自包含的 JSON（通常 1～3 MB），**离线看它就能把接口层和解析层写对**。
大约需要 30～60 秒。

这套机制本身也是我需要的"证据入口"：只要它在，就不必再靠一轮一轮的猜测去逼近真相。

## 10. 开发与测试

```bash
node tools/gen-icons.mjs     # 重新生成图标（零依赖手写 PNG）
node tools/gen-key.mjs       # 生成固定扩展 ID 用的公钥（换机构/换机器时才需要）
node tools/validate.mjs      # 静态完整性校验（改完代码先跑这个）
node tests/run.mjs           # 解析层测试（纯 Node，无需浏览器）
```

`tools/validate.mjs` 会检查 300 多项，覆盖最容易“一装就炸”的几类问题：

- manifest 里引用的文件是否都存在
- 所有相对 `import` 能否解析，**以及被导入的具名导出是否真的存在**
  （少写对一个导出名，整个模块会在浏览器里直接加载失败）
- HTML 引用的 css/js 是否存在
- UI 脚本里 `$('#id')` 用到的每个 id，是否真的写在对应 HTML 里
- 消息协议是否对齐：UI 发的 `MSG.*` 在 Service Worker 里都有 handler，反之亦然

这几条不是摆设 —— 开发过程中正是它们（以及真机冒烟）拦下了三个会让扩展**完全打不开或整体失效**
的错误：`default_locale` 声明了却缺少 `_locales` 目录、`dashboard.js` 从错误的模块导入 `HOUR`、
以及 UI 绑定函数里一个 id 写错就会中断后面全部绑定把面板变成一块死界面。

测试套件（`node tests/run.mjs`，540 条断言）则是用对抗性审查的方式写的：它一开始专门去
**证伪**解析层的假设，抓出并固定了 9 个真实缺陷（页面身份误判、把「1.2 MB」当成 1 月 2 日、
把提交日期当截止时间、td 级候选盖过行级候选、短课程列表里每门课继承第一张卡片的教师……）。
缺陷修好之后那一组被改写成回归测试，防止再踩回去。

### 真机冒烟测试

用无头 Edge/Chrome 直接加载扩展并渲染页面，是发现运行时错误最快的方法：

```bash
msedge --headless=new --disable-gpu --no-sandbox --no-first-run \
  --user-data-dir=/tmp/prof --load-extension=<本目录> \
  --enable-logging=stderr --virtual-time-budget=11000 --dump-dom \
  chrome-extension://ncgioopojlgncgpjkflkhijfojpnmipo/src/dashboard/dashboard.html
```

（ID 由 `manifest.json` 里的 `key` 固定，所以上面这个地址是稳定的。）
在 stderr 里能看到 Service Worker 的启动日志，`--dump-dom` 的产物能确认页面真的渲染出了内容。

### 面板渲染预览（不需要账号也能跑）

`tests/preview/mock-dashboard.html` 是一个用**假数据**驱动真实面板的页面，
把它按上面的方式加载就能在无头浏览器里检查卡片形态、截止倒计时、颜色档位、跳转链接：

```bash
msedge --headless=new --disable-gpu --no-sandbox --no-first-run \
  --user-data-dir=/tmp/prof --load-extension=<本目录> \
  --virtual-time-budget=9000 --dump-dom \
  chrome-extension://ncgioopojlgncgpjkflkhijfojpnmipo/tests/preview/mock-dashboard.html
```

上一次渲染结果留在 `tests/preview/last-render.html`，可以直接看。

写这个预览页时踩到两个坑，都值得记下来：

1. **扩展页面不能有内联 `<script>`** —— MV3 的 CSP 是 `script-src 'self'`，
   内联脚本会被直接拦掉（控制台报 `Executing inline script violates ...`）。
   所以 mock 必须放在 `mock-chrome.js` 这样的独立文件里。
   症状很有迷惑性：面板会照常渲染，只是拿到的是真实后台的空状态，看起来像“mock 没写对”。
2. **扩展页面上的 `window.chrome` 是真实 API**，`window.chrome = {...}` 这种整体替换
   在非严格模式下会**静默失败**。必须用 `Object.defineProperty` 逐个覆盖
   `runtime` / `permissions` / `tabs`，并自己断言覆盖是否真的生效。

`tests/minidom.mjs` 是一个零依赖的迷你 DOM 实现，专门为了让解析器能在 Node 里被真正执行——
不是把断言 mock 掉，而是把 HTML 真解析成节点树（包括浏览器那种 `<tr>` 自动包 `<tbody>` 的行为）。

### 打包发布时

`tests/` 与 `tools/` 只在开发时用得到，正式打包（zip / 上架）时删掉它们即可，
扩展运行不依赖这两个目录里的任何文件。

## 11. 开发过程中被验证修正的两个关键假设

把这两条写下来，是因为它们对后来者最有用：

1. **最初的设计是「fetch 页面 HTML + DOMParser 抽取」。它在这个站点上完全行不通。**
   证据来自站点自己前端资源里的课程列表页模板：页面里只有 `<div id="selfcourse"></div>`
   和一个 `<script type="text/html" id="tablist">` 的 mustache 模板（`{{value.kcid}}` 占位符），
   公告/文件/作业则分别由 `pageListXsSearch` / `xspageList` / `v_xszy_search` 三个
   DataTables 服务端分页接口填充。**原始 HTML 里一条数据都没有。**
   → 于是才有「接口优先 + 渲染兜底」的两层结构。

2. **最初以为登录页是一个本地账号密码表单，可以自动提交。**
   实际是学校统一身份认证（`id.tsinghua.edu.cn`，页面资源里有 `captcha.jpg`、
   `fingerprintUtil.js`、`doubleauth/localstorageUtil.js`），而且站点历史上那个
   `/b/j_spring_security_check` 已废弃（上游 `thu-learn-lib` 有对应 issue）。
   → 于是把「自动登录」改成「自动填充 + 引导用户完成验证」，并在 UI 上如实说明，
   而不是做一个看起来很酷但必然失败的假自动登录。

## 12. 设计取向说明

用户最初建议参考 [`smartThise/NextTHUxk`](https://github.com/smartThise/NextTHUxk)（下一代选课）。
实话说：**该项目除了仓库描述外几乎没有公开可检索的资料**（没有 README 内容、没有文件树、
没有第三方文章），所以「照它的样子做」客观上不可行。本项目的取舍来自清华相关工具的**生态惯例**，
这些是可查证的：

- 内容脚本注入既有站点 + 一个独立的整页 UI（而不是只有弹窗）——弹窗尺寸受限、关掉即丢状态；
- 按**对象类型**分标签（公告 / 作业 / 文件），因为这就是网络学堂自己的数据模型；
- 课程列表作为常驻左侧栏，内容区按课程过滤；
- 截止时间用**徽标 + 倒计时 + 颜色档位**表达，而不是写进正文；
- 注入到别人页面的样式全部加 `.thul-` 前缀，避免和站点 CSS 打架；
- 把「取数据」和「展示」分层（生态里 `thu-learn-lib` 就是这个角色），站点改版时只改取数层。

## 13. 已知限制

- 登录必须由你本人在统一身份认证页面完成（验证码 / 二次认证），扩展不代劳。
- 接口参数是「超集」策略：DataTables 版本的参数名无法从前端压缩代码里完全确认，
  因此同时发送 1.9 与 1.10 两代命名；若站点校验严格拒绝多余参数，会自动退回渲染兜底路径。
- 课程名在某些接口版本里不含学期/教师信息，缺失时面板会留空而不是编造。
- 讨论 / 答疑 / 问卷板块尚未纳入（数据结构已预留，欢迎扩展）。
- **雨课堂的「已完成」是推断口径**：`done >= total`（题数做完）判为已完成，
  只观测到一条正向样本、没有反例可校验。所以面板上显示成「已完成 2/2 / 未完成 0/6」
  这种带进度的措辞，而不是权威的「已交/未交」。若你发现某条判错了，把那条的情况告诉我。
- **雨课堂课程归类靠课程名**：两边名字差得太多（例如一边带教师名、一边没有）就可能对不上。
  对不上的课程会在面板上明确列出（有作业却没地方放时会报警），不会静默丢弃。
